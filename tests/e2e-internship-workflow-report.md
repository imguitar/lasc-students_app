## 3. ลำดับ Workflow ของระบบเทียบกับสเปก

ลำดับในระบบจริงต่างจากสเปก การทดสอบยึดลำดับของระบบ:

1. นักศึกษายื่นคำร้อง: `รออาจารย์ที่ปรึกษาอนุมัติ`
2. อาจารย์อนุมัติ: `รอผู้ดูแลระบบอนุมัติ`
3. แอดมินอนุมัติและแนบหนังสือขอความอนุเคราะห์: `รอสถานประกอบการตอบรับ`
4. สถานประกอบการตอบรับผ่านลิงก์ใช้ครั้งเดียว: `สถานประกอบการตอบรับแล้ว (รอผู้ดูแลระบบกำหนดวัน)`
5. นักศึกษาส่งสลิป แอดมินอนุมัติสลิป และกดเริ่มฝึก: `ออกฝึกงาน`
6. แอดมินกำหนดผู้นิเทศ อาจารย์บันทึกผลนิเทศ ระบบส่งลิงก์ประเมินให้พี่เลี้ยง และสถานประกอบการประเมิน: `ฝึกงานเสร็จแล้ว` (อัตโนมัติเมื่อประเมินครบสองฝ่าย)
7. แอดมินปิดงาน: `เสร็จสิ้นสมบูรณ์` (ไม่มีปุ่มบนหน้าจอ ทดสอบผ่าน API)

สเปกให้สถานประกอบการตอบรับก่อนอาจารย์ แต่ในระบบ สถานประกอบการตอบรับหลังจากแอดมินออกหนังสือแล้ว

## 7. Sign-off

**ข้อสรุป: ยังไม่พร้อมใช้งานจริง (Not ready for production)**

ด้านที่ทำงานถูกต้อง:

- **Workflow หลักครบทั้งลูป** ตั้งแต่ยื่นคำร้องจนปิดงานสำเร็จผ่าน API
- **คำนวณวันสิ้นสุดฝึกถูกต้อง** ข้ามเสาร์-อาทิตย์และวันหยุดในฐานข้อมูล (ข้ามวันที่ 7 และ 10 ธันวาคม 2569) ตรงกับการคำนวณแยก
- **ลิงก์ตอบรับของสถานประกอบการปลอดภัย** ใช้ได้ครั้งเดียว และต้องมีลายมือชื่อ
- **รายงานประจำวันแยกตรงเวลา/ย้อนหลังถูกต้อง** มี timestamp เวลาส่งจริง บังคับลายเซ็นพี่เลี้ยงเมื่อลงย้อนหลัง กันการลงล่วงหน้า ลงก่อนวันเริ่ม และลงซ้ำ
- **ปิดสถานะอัตโนมัติ** เมื่อประเมินครบสองฝ่าย
- **อีเมลที่ระบบสร้าง** มีโครงสร้างครบ และลิงก์ถูกต้อง

สิ่งที่ต้องแก้ก่อนเปิดใช้งานจริง:

1. **สิทธิ์ของ API (Critical 2 รายการ)** นักศึกษาเปลี่ยนสถานะคำร้องของตัวเอง และอนุมัติสลิปของตัวเองได้ ต้องเพิ่มการตรวจบทบาทและการตรวจลำดับสถานะที่ backend
2. **ตั้งค่าการส่งอีเมล (Critical)** ปัจจุบันไม่มีอีเมลฉบับใดถึงผู้รับจริง
3. **ปัญหา Major 5 รายการ**
   - อีเมลถึงแอดมินหายเพราะชื่อสถานะไม่ตรงกัน
   - ปุ่มมอบหมายผู้นิเทศใช้ไม่ได้
   - นัดนิเทศจากหน้าอาจารย์ล้มด้วย 500
   - แบบประเมินสาธารณะไม่มี token
   - บันทึกรายงานแทนผู้อื่นได้

หลังแก้ข้อ 1–3 ควรรันชุดทดสอบนี้ซ้ำเพื่อยืนยัน

## ภาคผนวก: วิธีรันซ้ำ

ไฟล์ชุดทดสอบอยู่ที่ `tests/e2e/`

- `cap.js`: ตัวดักอีเมล
- `run.js`: สคริปต์ทดสอบ
- `cleanup.sql`: ล้างข้อมูลทดสอบ

ผลและหลักฐานจากการรันครั้งนี้อยู่ที่ `tests/e2e-artifacts/`

```bash
export MSYS_NO_PATHCONV=1   # เฉพาะ Git Bash บน Windows
docker exec lasc-coop-backend mkdir -p /tmp/e2e/mails
docker cp tests/e2e/cap.js lasc-coop-backend:/tmp/e2e/cap.js
docker cp tests/e2e/run.js lasc-coop-backend:/tmp/e2e/run.js
# เปิดเซิร์ฟเวอร์ทดสอบที่พอร์ต 5099 พร้อมตัวดักอีเมล (ค่า Gmail ปลอมเพื่อให้เดินเส้นทางส่งจริงจนถึงตัวดัก)
docker exec -d -w /app -e PORT=5099 -e E2E_MAIL_DIR=/tmp/e2e/mails \
  -e GMAIL_USER=e2e-sender@example.invalid -e GMAIL_CLIENT_ID=e2e-dummy \
  -e GMAIL_CLIENT_SECRET=e2e-dummy -e GMAIL_REFRESH_TOKEN=e2e-dummy \
  lasc-coop-backend sh -c 'exec node -r /tmp/e2e/cap.js src/server.js > /tmp/e2e/server.log 2>&1'
docker exec -w /app lasc-coop-backend node /tmp/e2e/run.js
# ล้างข้อมูลทดสอบหลังเก็บผล
docker exec -i lasc-mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 lascstudent' < tests/e2e/cleanup.sql
```

ข้อควรระวัง:

- ห้ามรันชุดนี้กับ backend ที่ตั้งค่า Gmail จริงโดยไม่มี `-r /tmp/e2e/cap.js`
- `run.js` ตั้งวันเริ่มฝึกเป็น 2026-11-02 และเลือกวันลงย้อนหลังเป็นสองวันก่อนวันที่รัน ถ้ารันในวันอื่นให้ตั้ง `E2E_START` เป็นวันจันทร์ที่ไม่เกินสองวันก่อนวันรัน
